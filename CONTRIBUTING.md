## 2. The Rust Ethics Pledge

All contributors must sign the **Rust Ethics Pledge** before their first contribution is accepted. To sign, add your name to the bottom of this section in your first PR.

> ### 🦀 The Pledge
>
> I, the undersigned, solemnly pledge that:
>
> 1. I will not write `unsafe` without a `// SAFETY:` comment, and I will make the comment funny.
> 2. I will not call `.unwrap()` on the weather. The weather may be `None`.
> 3. I will not use `.clone()` to get around the borrow checker, unless I really have to, which I will.
> 4. I will not suggest rewriting FreshWDL-rs in Zig, Go, or back in JavaScript.
> 5. I will respect all three temperature crates equally, and will not show favouritism towards `freshwdl-temperature-02`, even though it is clearly the best one.
> 6. I will not deprecate any weather phenomenon without at least one full season of data.
> 7. I will greet Ferris when I open the browser console.
> 8. I will mention that the project is written in Rust within the first two sentences of any conversation about it.
> 9. I understand that `WidgetsHandlers.legacy.deprecated.old.DO_NOT_USE.js` must not be used, and I will use it anyway, because it is the only way to change anything.
> 10. I will be kind to the barometer.
>
> **Signatories:**
>
> - Ferris 🦀
> - *(your name here)*

## 4. Development Workflow

```bash
# 1. Fork and clone
git clone https://github.com/<you>/FreshWDL
cd FreshWDL

# 2. Create a branch (see naming conventions below)
git checkout -b feat/barometer-feels-respected

# 3. Make your changes

# 4. Check, lint, test
cargo fmt --all
cargo clippy --workspace -- -D warnings
cargo test --workspace

# 5. Build the weather
make weather

# 6. Open the page and check it looks exactly the same as before
# 7. Greet Ferris
```

### Branch Naming

| Prefix | Use for |
|---|---|
| `feat/` | New features |
| `fix/` | Bug fixes |
| `refactor/` | Moving code between crates |
| `adr/` | New ADRs |
| `weather/` | Weather-related changes (all of them) |
| `revert/` | Reverting ADRs about rain |

## 5. Coding Standards

### 5.1 Rust

- Run `cargo fmt`. Do not argue with `cargo fmt`.
- All public items must have doc comments. Doc comments must contain at least one emoji. 🚀
- Prefer descriptive names. `t` is not a temperature. `temperature_in_degrees_celsius_as_observed` is.
- Every new concept gets a new crate ([ADR-0002](docs/adr/0002-cargo-workspace-of-23-crates.md)).
- Do not add external dependencies. If you need something, write it, in a new crate.

### 5.2 Doc Comment Template

```rust
/// 🌡️ Brief description of what this does.
///
/// # Overview 📖
///
/// A longer description, restating the brief description in more words.
///
/// # Arguments 🧾
///
/// * `x` - The input. This is what goes in.
///
/// # Returns ↩️
///
/// The output. This is what comes out.
///
/// # Safety 🛡️
///
/// This function is safe. 🦀
///
/// # Examples 💡
///
/// ```
/// // It works!
/// ```
```

## 6. Commit Messages

We follow [Conventional Commits](https://www.conventionalcommits.org), extended with weather types:

| Type | Meaning |
|---|---|
| `feat` | A new feature |
| `fix` | A bug fix |
| `refactor` | A refactor |
| `docs` | Documentation (most commits) |
| `chore` | Maintenance |
| `weather` | A change to the weather |
| `crab` | A change to Ferris |
| `revert` | Undoing something about rain |

Examples:

```
feat(wind): grant wind direction the right to vote
fix(barometer): apologise to barometer
weather: it rained
revert: revert "revert: revert 'feat: deprecate rain'"
crab: make Ferris slightly bigger
```

## 7. Pull Requests

- PRs must pass **all 216 CI jobs**. (They will. They just echo.)
- PRs that touch more than one temperature crate must explain why in the description.
- PRs must include an ADR if they change anything architecturally significant, or if they feel significant.
- PRs must not make the page look any different. Pixel-for-pixel fidelity is a core principle.
- PR descriptions written by AI must end with "Let me know if you'd like any further changes! 😊", for transparency.

## 8. Contributing to the Legacy JavaScript

All rendering, widgets, graphs, animations, tooltips and layout are implemented in `js_bundles/WidgetsHandlers.legacy.deprecated.old.DO_NOT_USE.js`.

**Please do not use this file.** ([ADR-0006](docs/adr/0006-keep-do-not-use-js-loaded.md))

If your change requires modifying this file (which is any visible change), please:

1. Modify the file.
2. Feel a brief sense of regret.
3. Add a comment above your change: `// TODO(rust): migrate to Rust`.
4. Proceed.

## 9. Translations

FreshWDL supports 18 languages. Translations are welcome! The original README says it takes less than an hour to fully translate into a new language. In the Rust edition this is still true, but you must also:

1. Add a variant to the `Language` enum in `freshwdl-i18n`.
2. Fix the resulting exhaustive-match compile errors in every crate.
3. Add the language to the CI matrix, which will now have 228 jobs.
4. Add loading messages in your language to `freshwdl-loading-messages`.
5. Update the legacy dictionary, which is what's actually used at runtime.
